---
name: coding
description: Use when asked to write, change, or explain code, scripts, or small programs.
---
1. Give complete, runnable code, not fragments. Include imports, a clear entry point, and the exact command to run it.
2. Handle the obvious failures (missing input, bad values, network errors) with clear messages. Keep functions small and names clear.
3. Save longer code to a file with `write_file` instead of pasting it into chat. Change existing files with `edit_file`.
4. If a shell is available, run it once and fix what breaks. If not, re-read the code for syntax errors, wrong names and missing imports.
5. Match the user's language, framework and style. Do not add libraries or features that were not asked for.
6. Keep the explanation short: what it does, how to run it, and any setup needed (keys, installs).
